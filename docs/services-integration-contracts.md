# منصة تنميات — البنية التشغيلية للخدمات الست

**نطاق التنفيذ:** نواة تقنية متصلة بحسابات وصلاحيات تنميات، ومؤهلة لربط مزودي الخدمات لاحقاً. هذه الحزمة لا تتضمن معاملات مالية حقيقية ولا بثاً عبر مزود خارجي ولا استدعاءات نماذج توليدية قبل الربط.

## البنية المشتركة
- المخطط: migrations/0025_services_core.sql (إضافي، لا يحذف البيانات القائمة).
- المسارات: /api/platform/... في src/platform-services.js، والتحقق بجلسة العضو الحالية مع حدود معدل لكل عملية.
- الواجهة: /services عبر public/platform-services.js و public/platform-services.css.
- الإعدادات العامة: tn_service_config، وأوضاع disconnected / testing / ready.
- أسرار التكامل: توضع في متغيرات Cloudflare Workers السرية أو نظام أسرار معتمد، ولا تحفظ في D1 ولا تظهر في الواجهة.
- تحويل الخدمة إلى ready لا يضمن سلامتها؛ يلزم فحص تطبيقي بمزود حقيقي وتوثيق فشل الطلبات.

## 1. تنميات AI التوليدي
**المنجز:** غرف محادثة مستقلة، ملكية حساب، حفظ رسائل المستخدم، استرجاع السجل، هيكل source_refs، حدود طلبات، واجهة محادثة.
**نقطة الربط:** إنشاء AIProvider.generate({messages,knowledgeReferences,model,temperature}) في طبقة خادم؛ إعداد المفاتيح من أسرار الخادم فقط، وربط استرجاع مقالات الموسوعة بمراجع محددة ودرجة تحقق.
**التفعيل المستقبلي:** تدقيق المصادر وفلترة محتوى حساس، فواتير الاستهلاك والحصص، رسالة assistant تحفظ بعد نجاح generation فقط. لا تُولّد حالياً إجابات تلقائية، ورسائل المستخدم تحفظ دون إرسالها إلى مزود خارجي.
**خصوصية:** لا تعرض محادثات الأعضاء للآخرين، والحذف والاحتفاظ بحاجة لإكمال قواعد صريحة قبل تفعيل AI.

## 2. البث المباشر
**المنجز:** بيانات جلسات البث، حالات draft/cancelled، إنشاء/إلغاء، لوحة صاحب البث، فحص الكاميرا والميكروفون محلياً.
**نقطة الربط:** LiveProvider.createBroadcast, issueStreamKey, startFromVerifiedWebhook, stopFromVerifiedWebhook, playback; مع توقيع webhook ومفاتيح بث مؤقتة وحقوق وصول.
**ضابط:** لا يحق للعميل تعيين حالة live مباشرة؛ الخادم لا يعلن بثاً عاماً إلا بعد إثبات وصول فعلي من مزود البث.

## 3. مكالمات صوتية ومرئية
**المنجز:** دعوات محصورة بالأصدقاء، قبول/رفض/إنهاء، صلاحيات المشاركين، إشارات offer/answer/candidate، WebRTC peer connection بواجهة محلية وصوت وكاميرا، إنهاء وإيقاف الأجهزة.
**نقطة الربط:** خوادم STUN/TURN وشهادات نقل وتحديثات إشارات آنية بدلاً من polling؛ رصد انقطاع المكالمات، حماية من الإزعاج والحظر/الإبلاغ، وسياسة احتفاظ قصيرة بالإشارات.
**الحد:** من دون STUN/TURN قد يعمل الاتصال على شبكات مباشرة محددة، لكنه ليس خدمة اتصال موثوقة عبر الإنترنت. لا تخزن الوسائط في D1، وإشارات SDP/ICE تخزن مؤقتاً حتى تطبيق دورة تنظيف.

## 4. خصوصية الملف الشخصي
**المنجز:** أربعة نطاقات رؤية (عام، أعضاء، أصدقاء، أنا فقط) لحقول النبذة والميلاد والمناسبات والملف المهني؛ إعدادات خاصة محفوظة ونافذة تحرير؛ فرض خصوصية النبذة من API الملف ودليل الأعضاء واستكشافهم، وخصوصية الملف المهني عند البحث والعرض.
**الوضع الفعلي:** تاريخ الميلاد والمناسبات مخزنان بشكل خاص ولا يتم نشرهما أصلاً؛ خيارات إظهارهما لأشخاص محددين تحتاج API قراءة مقيّداً لاستخدامها مستقبلاً. لا تُعرض بيانات خاصة عبر CSS وحده.
**الاختبار:** منع الكشف عن الحقول في أي endpoint آخر قبل إضافة مزيد من الواجهات.

## 5. منظومة Reels
**المنجز:** جدول مستقل للمقاطع، ملكية وخصوصية ومراحل نشر، حفظ مسودات الفيديو، منشورات MP4 المملوكة، قائمة مقاطع عامة عمودية قابلة للتشغيل داخل /services، وفلترة ظهور المصدر حسب حالة الإشراف.
**نقطة الربط:** R2/Stream أو منصة وسيطة لرفع ملفات طويلة، transcode وposter وHLS وCDN ومقاييس مشاهدة. يجب تطبيق صلاحيات الوصول إلى ملف الوسائط نفسه قبل تقديم فيديو خاص جديد.
**الحد:** تستخدم مسودات هذه المرحلة فيديو منشوراً بالفعل؛ اختيار private يخص ظهور Reel في كتالوج Reels، ولا يحوّل المرفق الأصلي المنشور إلى ملف خاص.

## 6. الدفع والتحصيل والعمولات
**المنجز:** مسودات طلبات صالحة ومقيّدة بالمالك، مبالغ بوحدة أصغر، سياسة عمولة إدارية بالنقاط الأساسية والرسم الثابت، احتساب العمولة وحفظها مع الطلب، جداول events وsettlement entries قابلة للربط، واجهة إدارة سياسة العمولات.
**نقطة الربط:** PaymentProvider.createIntent, verifyWebhook(signature,rawBody), fetchPayment, refund, settle.
**ضمانات إلزامية عند الربط:** التحقق من التوقيع وتكرار webhook، idempotency، انتقالات حالات قانونية (draft/awaiting_payment/paid/cancelled/refunded)، منع تغيير paid من المتصفح، دفتر محاسبي موزون، reconciliation يومي، التزامات الفوترة والضرائب والامتثال، حماية بيانات الدفع دون حفظ بيانات البطاقات.
**الحد:** لا توجد عملية تحصيل أو صرف أو تأكيد دفع أو عمولة مستحقة قابلة للصرف حالياً. كل الأوامر المالية المضافة مسودات ولا تمثل بيعاً ملزماً.

## اختبار ونشر آمن
1. الاحتفاظ بفرع feature/tnmyat-services-core منفصلاً عن الإصدار المنشور لحين اجتياز اختبارات CI.
2. إنشاء نسخة D1 تجريبية من مخطط قاعدة إنتاج حديث من دون تعريض بيانات المستخدمين، ثم تجربة ترحيل 0025.
3. تشغيل npm test ومراجعة اختبارات tests/platform-services.test.js؛ ثم تجربة سطح المكتب والجوال والحساب الضيف والعضو والإدارة.
4. نسخة احتياطية حديثة مؤكدة قبل أي تطبيق ترحيل على tnmyat-db.
5. لا تنشر الواجهة والخادم قبل تطبيق الترحيل واختباره؛ عدم توافق المخطط قد يسبب أخطاء 500.
6. نشر تدريجي خلف صلاحيات/تفعيل مرحلي، مع مراقبة الأخطاء وتحديد خطة roll-forward. إعادة إصدار Worker لا تعيد بيانات D1 وحدها.
7. لا تُفعّل خدمات AI أو البث/الاتصال العام أو الدفع للمستخدمين حتى اعتماد مزوديها والتدقيق النظامي والأمني.

## مخاطر تقنية يجب معالجتها قبل الإطلاق التجاري
- حماية ومدة احتفاظ محادثات AI وإشارات المكالمات، وتشفير البيانات الحساسة والقدرة على حذفها.
- منع إساءة استخدام المكالمات والبث، وإشراف محتوى الفيديو ومراقبة الإساءة.
- تأمين ملفات Reels غير العامة وإدارة تغيير خصوصية المنشور الأصلي.
- سجلات تدقيق الدفع، سلامة حالات التسوية، ونظام استرداد الأموال وتسوية النزاعات.
- مراجعة جميع مصادر حقول الملف المهني والشخصي عند إضافة نقاط عرض جديدة.

**التطوير الحالي فعلي وقابل للتجربة داخل المنصة، لكنه مقصود أن يبقى قبل مرحلة الربط التجاري.**
